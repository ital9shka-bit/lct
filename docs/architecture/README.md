# Схемы архитектуры в нотации C4

Это два **Container view** одной системы: [AS IS](architecture-as-is.png) показывает работающий стенд, [TO BE](architecture-to-be.png) — предложенные расширения. Тип элемента написан на каждой карточке; цвет и легенда помогают различить приложение, данные и сетевые сервисы. Стрелки однонаправленные и подписаны протоколом или действием.

Граница «СтройКонтроль» логическая: бакет S3 относится к данным системы, хотя размещён во внешнем хранилище. GateLLM — сервис того же владельца, но отдельная сетевая система по отношению к стенду; Rusender — почтовая интеграция. На AS IS Caddy и Nginx объединены в один узел «веб-вход» для читаемости; физически это два контейнера Compose. Подробности развёртывания — `compose.prod.yaml` и `deploy/Caddyfile`.

TO BE не является описанием реализованного кода. В предложении задания хранятся в PostgreSQL и выполняются отдельным worker; выбор GateLLM / Yandex AI Studio проходит через проверенный адаптер. SMS и edge-агент требуют отдельного внедрения.

Источник нотации: [официальное описание Container diagram](https://c4model.com/diagrams/container) и [правила обозначений](https://c4model.com/diagrams/notation). PNG воспроизводятся командой `.venv/bin/python scripts/build_architecture_diagrams.py` в исходном проекте.
