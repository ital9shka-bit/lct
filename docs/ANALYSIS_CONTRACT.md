# W0 — контракт анализа

Статус на 19 сентября 2026 года: W0 выполнен. Живой ответ GateLLM прошёл строгую схему и семантическую валидацию.

Этот документ фиксирует исторический прогон W0 с `construction-analysis-v1`. В опубликованном демо с 27.09 используется `construction-analysis-v2`: он уточняет, что частичная наблюдаемость этапа в каталоге сама по себе не делает полностью видимую рабочую зону недостаточно покрытой. Пороги `thresholds.v1.json` не менялись; результат текущего демо описан в `qa/DEMO_READINESS_2026-09-28.md`.

## Что реализовано

- Демо-справочник `config/analysis/stage-catalog.v1.json`: три типа объектов и три этапа основного объекта — разработка котлована, монтаж башенного крана, внутренние инженерные сети.
- Версионированные профили признаков. Техника сама по себе не подтверждает земляные работы.
- Строгая схема пяти частей `config/analysis/analysis-response.schema.v1.json`.
- Промпт `construction-analysis-v1`, который запрещает выдумывать невидимые работы и суммировать технику между камерами.
- Вход W0 из трёх существующих фотографий с закреплёнными SHA-256.
- Клиент OpenAI-совместимого API для `responses` и `chat_completions`, сохранение сырого ответа, нормализованного ответа, request id, времени, токенов и оценки стоимости.
- Перед отправкой копии кадров уменьшаются до 1024 пикселей по длинной стороне и кодируются в JPEG 75; исходные файлы не меняются. Параметры выбраны после двух ответов `413 Payload Too Large` от GateLLM и записываются в манифест запуска.
- Серверная семантическая валидация идентификаторов и связей поверх JSON Schema.
- Подтверждённые пороги `thresholds.v1.json`, синтетическая фикстура для негативных тестов и отдельная живая фикстура GateLLM.

## Результат живого прогона

| Параметр | Значение |
| --- | --- |
| Провайдер и модель | `gatellm`, `openai/gpt-5.6-luna` |
| API | `POST /v1/chat/completions` |
| Промпт | `construction-analysis-v1` |
| Транспортные изображения | JPEG 75, длинная сторона до 1024 px |
| Длительность | 13 463 мс |
| Токены | 4 144 входных, 2 017 выходных, 6 161 всего |
| Стоимость из ответа провайдера | 0,00345625 USD |
| Request id | `gen-1789821321-v1ePiZYs0rdD2ibiJC8Q` |

Котлован подтверждён с уверенностью 0,99 по двум связанным камерам. Этап крана получил 0,94: установленные мачты и стрелы видны, а отсутствие наблюдаемой операции сборки записано ограничением. Внутренние сети корректно получили `not_observable` и требуют осмотра.

Положительные свидетельства лежат в диапазоне 0,93–0,99, неоднозначные признаки сборки крана — 0,45–0,48. Начальный порог 0,72 оставлен без изменения. Порог явного отсутствия 0,70 зафиксирован консервативно и должен получить отдельный отрицательный набор на W3/W4.

## Запуск

Проверить входные файлы, каталог и конфигурацию без внешнего вызова:

```sh
python3 scripts/run_w0_analysis.py --dry-run
```

Запустить реальный запрос после экспорта переменных из `.env.example`:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements-w0.txt
AI_API_KEY='...' .venv/bin/python scripts/run_w0_analysis.py --promote-fixture gatellm-luna-w0-v1
```

Ключ никогда не записывается в артефакты. Результат конкретного запуска появляется в `artifacts/w0-runs/<UTC timestamp>/`, а при `--promote-fixture` проверенный нормализованный ответ и метрики копируются в `config/analysis/fixtures/live/`.

Живой прогон подтвердил, что GateLLM принимает эту модель через Chat Completions. Маршрут Responses API вернул `404` и остаётся доступным в адаптере только для других совместимых провайдеров. Автоматического переключения между форматами нет, чтобы один запуск не создал два платных запроса.

## Итог этапа

- W0.2: выполнен живой прогон трёх фотографий, схема из пяти частей пригодна, время и стоимость измерены.
